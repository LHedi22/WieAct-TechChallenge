## Decided
- 2026-10-30 · Class Wisdom retries (user-approved): a WISDOM_TIP job has no payer (cost 0), so a failed tip refunds nothing because nothing was charged. A pattern whose tip failed at N distinct students is re-asked only when the count goes above N (`payload.students`), so neither a cached empty tip nor JSON still broken after the repair call can be re-requested on every quiz attempt
- 2026-10-30 · Loading-screen tips (user decision): only the current course's Class Wisdom; a course with none shows a general study tip (static, translated, no AI, labelled "Study tip"), never another course's tips. The Quiz Hall results card shows this course's tips or nothing
- 2026-10-30 · M7 Audio Studio: one episode per chapter+level+language, a separate shared asset for `COST.generate_shared_asset` (wallet or Class Pool), ONE mid AUDIO_SCRIPT call (narrow-before-generating, final user-facing writing) → `{title, segments[]}` with formulas said in words; then free for the class. Played by the browser's Web Speech API segment by segment (highlight, play/pause, 0.75–1.5×): no audio is synthesised or stored by us. Darija, or a browser with no voice for the language → transcript only. The "opens soon" page is gone: all five buildings open
- 2026-10-30 · M7 Study Studio sells ONE study pack per chapter+level+language (notes + flashcard deck + mind map) for `COST.generate_shared_asset` (15), paid by the student or the Class Pool; then free for the whole class, including later joiners. A classmate opening it while it is generated shares the job for free. Level only, no personal style: the pack is shared, so style would split the cache
- 2026-10-30 · M7 calls per pack: 1 mid + 2 compact (plan-once / execute-compact). NOTES_WRITE (mid) writes from the narrowed chapter (same narrowing as the quiz pool, no filter call); FLASHCARDS and MAP_WRITE (compact) work only from those notes. **MAP_WRITE moved mid → compact**: turning existing notes into a tree is formatting, not reasoning, so this saves one mid call per pack
- 2026-10-30 · M7 failures: without usable notes the job fails and the payer is refunded (wallet or pool); a failed deck or map keeps the notes, the job ends `done` with `missing`, and filling the missing part later is free (the class already paid). Each part is saved as it lands, so a Defer resumes. The ai_cache key carries the job id: a rerun of the same job reuses a paid reply, a new job after an unusable reply makes a fresh call (`study_assets` is the class-wide cache)
- 2026-10-30 · M7 flashcards: SM-2 style, per student and card. Again → 60 s, ease −0.2 (floor 1.3); Good → 10 min, then interval × ease; Easy → 3 days, then interval × ease × 1.3, ease +0.15; ease starts at 2.5. Buttons show the server's next interval. Reviews are free. "Turn these into flashcards" on quiz results makes personal cards from missed (wrong, second-try, skipped) questions with NO AI call; idempotent per attempt
- 2026-10-30 · M7 Class Pool: a `class_pool_ledger` (contribute | spend | refund; balance = sum), no balance column. A gift (1–`MAX_CONTRIBUTION` 50) is also a spend row in the giver's `coin_ledger` and never comes back; recent gifts show nicknames only. Only shared-material generation can be paid from the pool (`payload.paid_by = "pool"`, reserved in the job's transaction under a per-world advisory lock); a failed job refunds the pool once. Empty pool → 402 `errors.pool_insufficient`, shown in place (only `errors.insufficient_coins` opens the out-of-coins screen)
- 2026-10-30 · M7 daily challenges: new type `flashcards` (review 10/20 cards); `daily_plan.md` v2 offers it only to a student who has cards (own or a class deck). CHALLENGE_ITEMS stays unused: the cards already exist
- 2026-10-30 · M6 daily challenge types are only what can be tracked today: answer N quiz questions, score ≥ X % on a chapter quiz, one graded Teach-Back explanation (peer or solo), finish a Socratic Tutor session. Flashcard challenges come with M7, and so does CHALLENGE_ITEMS: no M6 type needs generated items, so zero extra compact calls
- 2026-10-30 · M6 DAILY_PLAN never blocks: the first `GET /api/daily` of a Tunis day writes a rule plan (weak chapter → nearest exam → lowest mastery) and enqueues ONE background mid job (plan-once, cached per user+date).
